# T-15-1 — DEV: Whisperpine fg tree canopy renders as a black block over the party

**Role:** DEV · **Owned paths:** src/render/** (likely `src/render/diorama.ts`), scripts/** · coordinate with ART (`assets/regions/whisperpine/fg.png`) only if a code fix is impossible
**Severity:** major (found by T-14 QA)

## Problem
In Whisperpine Woods the foreground layer's top-left tree canopy (`assets/regions/whisperpine/fg.png`, the big tree at x 0–500 px, y 0–330 px of the 1920×1072 source) shows up as a flat, near-black, hard-edged pixel block.
- In combat at 1280×720 it covers the top half of the wagon and sits behind Lysa's and Oren's nameplates (x≈0–280, y≈180–410). The bottom edge is a straight staircase, not the painted leaves.
- On the map and end screens the same block hangs at the top of the screen (map: top-right x≈760–1280; win: top-centre x≈560–970).
Likely cause: `fgDrop` (combat) and the fg layout/anchor (`ANCHOR_Y.fg = 0`) move the tree so the trunk is off-screen and only the canopy is left floating mid-frame. The low `PAINT_SELF_LIGHT.fg` (0.35) plus pixelize then turns it into a black silhouette. At 844×390 the block is not visible, so the issue depends on aspect ratio.

## Repro
`npm run build && npm run e2e` (or `?seed=7&quality=high`, start a run, open the first Fight) → see `docs/qa/screens/final/combat-whisperpine.png`, `break.png`, `map.png`, `win.png`.

- Re-run `npm run e2e`. The new `combat-whisperpine.png` and `map.png` are clean, and the other regions look unchanged.
