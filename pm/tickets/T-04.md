# T-04 — DEV: src/sim — deterministic combat + run simulation, with unit tests

**Role:** DEV · **Owned paths:** src/sim/**, tests/unit/**, tsconfig.json / vitest.config.ts (only if needed)
**Inputs:** CLAUDE.md, pm/STATE.md, docs/content/GDD.md, src/data/types.ts, src/data/index.ts, src/data/validate.ts, src/data/balance.json (skim others as needed)

## Hard rules
- Pure TS. NO imports of three, DOM, window, document, performance, Math.random. Only src/data/** and src/sim/**.
- Deterministic: seeded RNG (mulberry32 or sfc32) in `src/sim/rng.ts`; same seed + same decisions ⇒ identical event log.
- Fixed timestep: `tick(dtSeconds)` with dt default 0.05 s at 1× speed (renderer may call with dt*speed).

## Deliverables
1. `src/sim/rng.ts` — seeded RNG (next(), int(a,b), pick(arr), chance(p), fork(label)).
2. `src/sim/combat.ts` — `class Battle` built from: party (hero states with level, skill ranks, current HP), formation (2×2: front/back rows × 2 slots), enemies (EnemyDef ids), relics, consumables, balance, rng. API:
   - `tick(dt): SimEvent[]` — advances ATB gauges by SPD, units act when gauge ≥ 100, returns events.
   - `canIgnite(): boolean`, `ignite(): SimEvent[]` — when the Ember meter is full, all living heroes immediately use their ultimate.
   - `state` (read-only snapshot: units with hp/maxHp/gauge/shield/maxShield/weaknesses/broken/status; emberMeter; time; outcome 'ongoing'|'win'|'loss').
   - SimEvent union: `{type:'action_start', actor, skill}`, `{type:'hit', source, target, amount, damageType, weakness:boolean, crit:boolean}`, `{type:'shield', target, shield}`, `{type:'break', target}`, `{type:'recover', target}`, `{type:'heal', source, target, amount}`, `{type:'status', target, status, on}`, `{type:'death', target}`, `{type:'ignite'}`, `{type:'ultimate', actor}`, `{type:'phase', target, phase}`, `{type:'ember', value}`, `{type:'end', outcome}`. Units are referenced by stable string uid (e.g. 'h:bram', 'e:0').
3. Rules: weakness hit −1 shield; at 0 ⇒ Broken: skips next action, takes ×breakDamageMult (1.5) for N actions (balance), then shield refills. Targeting: melee enemy attacks hit front row with 70% share (balance field), back row otherwise; if a row is empty, the other takes all; ranged may target anyone; AoE hits all. Hero AI per GDD: Bram taunt/guard lowest-HP ally; Lysa lowest-HP enemy or weakness match; Oren heal anyone < 50% else fire; Kit Broken enemy else highest-damage enemy. Skills (ranked 1–3) vs basic attack: use your data's cooldown/usage rule. Ember meter gains per hit/break (balance). Relic effects: implement every effect kind in types.ts in `src/sim/relics.ts` (hooks: onBattleStart, modifyStat, onHit, onBreak, onIgnite, onKill, onTurnStart…). Boss phases at HP thresholds (Hollow King 3 phases) emit `phase` events.
4. `src/sim/run.ts` — `class Run` (seed, hard?: boolean): generates the 4-region node map from map.json (3 steps × 2–3 choices + boss per region), tracks gold (Ember Shards), relics, consumables, party levels, HP carry-over between fights, curses. API: `availableNodes()`, `chooseNode(id)`, then per node type: `startBattle(formation) → Battle`, `finishBattle(battle)` (rewards, relic drops for elites, level-up after region boss), `camp(choice)`, `merchantStock()`, `buy(itemId)`, `event()`/`resolveEvent(choiceIdx)`, `pendingRelicChoice()`/`takeRelic(id)`, status 'map'|'battle'|'camp'|'merchant'|'event'|'reward'|'story'|'won'|'lost'. Story triggers after regions 1–3 and at start/end (just a field `pendingStory: sceneId | null` + `ackStory()`). Run stats object (fights, breaks, ignites, damage, time).
5. `src/sim/index.ts` re-exports.
6. Unit tests (vitest) in tests/unit/: rng determinism; weakness → shield → break → recover; break dmg multiplier; front-row 70% share statistically (±5%) over many seeded trials; Ignite requires full meter and triggers 4 ultimates; Oren heals under 50%; Hollow King hits all 3 phases when killed; same seed ⇒ same event log; Run produces 4 regions with correct node counts, total ~13 encounters; `validateContent()` returns []. 

## Acceptance
`npm run build` and `npm run test` pass. Report the test count, plus one example: a short battle summary (duration in sim seconds, winner) for a seeded region-1 fight and a Hollow King fight, using the default formation and no relics.
## Out of scope
Rendering, UI, the balance script (T-06), tuning numbers (you may tweak nothing in src/data; if data is broken/unimplementable, write the issue in pm/handoffs/T-04-data-issues.md).
